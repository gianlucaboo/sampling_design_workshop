Shiny

  • Shiny is an R package for building interactive web applications directly from R.
  • Originally developed for R by RStudio (now Posit), it is now available in Python.
  • Allows embedding of code, reactive UI elements (sliders, inputs, etc.), and outputs (plots, tables, etc.) that update when inputs change.

Shiny app structure

You can create a Shiny web app directly in R

Every Shiny app has two main parts:

1. UI (User Interface): defines layout and inputs/outputs visible to the user.

2. Server: defines how inputs are processed, computations, reactive expressions, outputs created.

Shiny app example

This is a structure of your shiny app.

library(shiny)

ui <- fluidPage(
  titlePanel("Hello Shiny"),
  sidebarLayout(
    sidebarPanel(
      sliderInput("bins", "Number of bins:", min = 1, max = 50, value = 30)
    ),
    mainPanel(
      plotOutput("hist")
    )
  )
)

server <- function(input, output, session) {
  output$hist <- renderPlot({
    x <- faithful$waiting
    hist(x, breaks = input$bins,
         col = "skyblue", border = "white",
         main = "Histogram of Old Faithful waiting times",
         xlab = "Waiting time")
  })
}

shinyApp(ui = ui, server = server)

ℹ️ Try to run the app using the Run app button.

Basic Reactive Concepts

  • Input functions/widgets: sliderInput(), selectInput(), textInput(), etc. provide
  • Reactive expressions/functions: computed when their inputs change, and those dependencies tracked automatically, for instannce when the slider input value changes.
  • Render functions: renderPlot(), renderText(), renderTable(), etc.
  • Output functions/widgets: plotOutput(), tableOutput(), etc.

Deployment & Sharing

  • Once you build a Shiny app, you can run it locally with runApp(), or launch via RStudio.

    • Your own Shiny Server
    • Posit Connect / other hosting platforms.

Tips & Best Practices

  • Keep reactive logic simple; avoid repeated heavy computations.
  • Use modularization for larger apps.
  • Monitor performance, especially for large data / many users.
  • Think about user interface design (visibility, ease of use).
  • Use logging / error handling.

Interactive Outputs: Maps, Plots, and Tables

Leaflet Maps

Use the leaflet package to add interactive maps:

library(shiny)
library(leaflet)

ui <- fluidPage(
  leafletOutput("mymap")
)

server <- function(input, output, session) {
  output$mymap <- renderLeaflet({
    leaflet() %>%
      addTiles() %>%
      addMarkers(lng = -122.4194, lat = 37.7749, popup = "San Francisco")
  })
}

shinyApp(ui, server)

Interactive ggplot with plotly

Combine ggplot2 and plotly to create interactive plots:

library(shiny)
library(ggplot2)
library(plotly)

ui <- fluidPage(
  plotlyOutput("plot")
)

server <- function(input, output, session) {
  output$plot <- renderPlotly({
    p <- ggplot(mpg, aes(displ, hwy, color = class)) + geom_point()
    ggplotly(p)
  })
}

shinyApp(ui, server)

Interactive Tables with DT

Use DT (DataTables) for interactive tables:

library(shiny)
library(DT)

ui <- fluidPage(
  DTOutput("table")
)

server <- function(input, output, session) {
  output$table <- renderDT({
    datatable(iris, options = list(pageLength = 5))
  })
}

shinyApp(ui, server)

Summary

  • Shiny lets you build reactive, interactive web apps using R.
  • You design UI, write server logic, and connect them.
  • You can create very simple or quite complex dashboards.
  • With deployment options, you can share your apps.
